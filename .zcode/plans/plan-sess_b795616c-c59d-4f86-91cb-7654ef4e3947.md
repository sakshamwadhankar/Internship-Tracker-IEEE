# Internship/Job Opportunities Section — Implementation Plan

## Goal
New "Opportunities" section in PTracker: user fills a profile (degree, branch, year, skills, interests, preferred roles/locations) → Firebase Cloud Functions aggregate internships/jobs from ~20+ websites on a schedule → keyword-matched, scored listings shown in the app with filters and bookmarks. (The Final-Year-Project Tracker PS belongs to your friend — this is a separate section in this app.)

## Architecture
- **Backend:** `functions/` directory (Cloud Functions gen2, Node 20). Two functions:
  - `scheduledSync` — Pub/Sub schedule every 6 hours; iterates source adapters, normalizes, dedupes, batch-writes to Firestore, deletes stale posts (>45 days), updates `sync_meta/{sourceId}` (lastRunAt, count, error).
  - `syncNow` — `onCall` (auth required) for a manual "Sync now" button in the UI.
- **Scraping policy (important):** prefer legal/free APIs; HTML scraping (cheerio, no headless browser) only for Indian boards that permit/ tolerate it, with 1–2s delays and per-source isolation so one failure never kills a run. LinkedIn/Indeed are **off by default** (ToS prohibit scraping) — included as optional flagged adapters.
- **Source registry (~18–21 adapters):**
  - *JSON APIs (9):* Adzuna (IN/GB/US), Remotive, Arbeitnow, Jooble, TheMuse, Jobicy, HN Who-is-Hiring (Algolia), SmartRecruiters, Careerjet — need 2–3 free API keys (Adzuna, Jooble) via `functions:secrets`.
  - *Company-board APIs (3):* Greenhouse, Lever, Ashby public JSON endpoints across ~50 target companies.
  - *Indian boards, HTML (6):* Internshala, Naukri, Unstop, Instahyre, LetIntern, Cutshort.
  - *Optional flagged (3):* LinkedIn guest, Indeed, Glassdoor — off by default.
- Each adapter: `{ id, name, region, kind: 'api'|'html', fetchJobs() → normalized[] }`.

## Data model (Firestore)
- `user_profiles/{uid}` — { degree, branch, gradYear, skills[], interests[], preferredRoles[], preferredLocations[], updatedAt }
- `opportunities/{dedupeHash}` — { title, company, location, country, type: 'internship'|'fulltime', source, applyUrl, tags[], description(truncated), postedAt, fetchedAt, stipend?, deadline? }. Doc ID = hash(company+title+applyUrl) → natural dedupe.
- `user_profiles/{uid}/saved/{oppId}` — bookmarks.
- `sync_meta/{sourceId}` — read: any authed user (powers "last synced" UI + per-source health).
- **Firestore rules update (includes fixing the P0 hole found in analysis):** scope existing goals/tasks/subtasks/user_preferences to `request.auth.uid == resource.data.userId`; new collections — profile/saved: own-docs only; opportunities: read any authed user, client writes denied (Admin SDK bypasses rules for the scraper).

## Client changes (existing patterns, vanilla JS)
- **Profile:** `renderProfileModal()` + save via new `saveUserProfile()`/`getUserProfile()` in a new `src/opportunities.js` store module (same listener/localStorage-cache pattern as store.js). Opened from Settings + from a "Complete your profile" prompt on the Opportunities screen.
- **New screen:** `'opportunities'` added to `ScreenType`, header pill + 6th dock icon (new `briefcase`/`heart` SVGs in `icons.js`). Screen = search bar, filter chips (All/Internship/Full-time · India/Global · sort by Match/Newest · Saved), opportunity cards with match-% badge, source badge, posted date, Apply link, save heart.
- **Matching (pure, tested):** `scoreOpportunity(profile, opp)` in `utils.js` → 0–100: skills overlap 50, role/interest keywords 20, location 15, degree/branch fit 10, recency 5. Matching runs client-side over recent opportunities.
- All user data through the existing `escapeHtml`; toasts for feedback; `state` gets `oppFilters` + cached profile.

## Config / testing
- `firebase.json`: add functions block (nodejs20). Requires **Blaze plan** enabled (free tier covers ~8k writes/day for 4 syncs). Keys via `firebase functions:secrets:set`.
- Tests: `tests/opportunities.test.js` (node --test, auto-picked up) for `scoreOpportunity` + filters; `functions/` tests with fixtures for the normalizer + 1 API adapter + 1 HTML adapter. README section: setup, keys, adding a source.

## Build order
1. Profile form + `user_profiles` store + full Firestore rules tightening.
2. Functions scaffold, normalizer/dedupe, 9 API adapters, `scheduledSync`/`syncNow`, sync_meta.
3. Indian HTML adapters + Greenhouse/Lever/Ashby company boards.
4. Opportunities screen UI + matching + saved/bookmarks + Sync-now.
5. Tests, README, end-to-end verify (deploy functions, run sync, check UI).

## Known risks
- Naukri/Unstop markup changes break adapters (isolated + health-visible in sync_meta); JS-rendered pages may need endpoint inspection during build. Scraped data is used internally as listings+links only.
